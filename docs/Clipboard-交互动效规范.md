# Clipboard 交互动效设计规范

> 基于当前界面结构（左侧分类栏 + 中间列表 + 右侧详情面板 + 底部操作栏）逐组件设计。
> 沿用同一套 duration/easing token，不重复定义，见文末附录。

---

## 一、顶部搜索框

**当前状态**：静态输入框 + `Ctrl+K` 快捷键提示徽标。

- **聚焦时**：边框颜色从灰变 Fluent 蓝强调色（`--accent` / `--border-focus` ≈ `#0078d4`），`duration-fast` + `ease-out`；同时 `Ctrl+K` 徽标做 `opacity 1→0.4`，暗示"已进入输入状态，快捷键提示让位"。
- **输入内容后开始搜索**：不做实时高亮动画本身的过渡（避免频繁重排），但**列表结果的增减**走"三、列表项"里定义的增删动效。
- **清空搜索**（如果有 clear 按钮）：按钮本身 `opacity 0→1` 随输入内容出现，`duration-instant`。

---

## 二、左侧分类栏（全部剪贴板 / 文本 / 图片 / 文件…）

**当前状态**：「全部」用强调色浅底高亮；各类型 / 收藏项激活态跟对应语义色（`--type-*` / `--warning`，经 `--cat-color`）。

- **切换分类**：背景色块不做位移滑动动画（因为是纵向列表、非同一容器内的横向 tab，位移反而会显得怪异），直接 `background-color` / `color` 过渡 `duration-fast`。
- **计数数字变化**（如 27 → 26，删除条目后）：数字本身不做滚动计数器效果（这类应用里数字变化频繁，滚动效果会变成噪音），直接切换 + 轻微 `opacity` 闪烁（`0.4→1`，`duration-instant`）提示"这个数字刚变了"。
- **标签管理区的彩色圆点标签**：hover 时圆点无动效，仅整行背景变化；自动打标用 sparkles 图标（静态，tooltip「自动打标规则创建」），不做动效，避免和用户手动操作的反馈混淆。0 计数标签收在「更多」折叠区。

---

## 三、中间列表（剪贴板条目）

这是全应用交互最密集的区域，规范要最细。

### 3.1 悬停态

行背景色变化，`duration-fast`。**同时**该行右侧的操作图标组（如当前选中行显示的 ↵ / 📌 / ⭐ / 🗑）从 `opacity 0` 渐显，`duration-fast`，而不是常驻显示——这样非 hover/选中状态下列表更干净，符合高密度信息流的诉求。

### 3.2 选中态（Fluent 列表浅底）

- 列表行为扁平 ListView 风格：无描边、无投影；hover 用 `--bg-hover`；选中用强调色浅底（`--accent` ≈ `#0078d4` 14%），圆角约 6px。类型色仍用于类型图标 / 链接标题，不拿来做整行描边。
- 点击列表项 → 背景过渡 `duration-fast`（不做 scale 弹跳）。
- **关键**：选中态确定后，右侧详情面板必须同步更新，且要让人明确感觉到"这两个区域在联动"——见下一节。

### 3.3 置顶 / 收藏（📌 与 ⭐ 分色）

- **颜色**：置顶用 `--pin`（紫，与删除红区分）；收藏用 `--warning`（金）。激活态、hover 加深都应同色系，不要共用一套 `action-active` / accent。
- **分组**：有置顶项时顶部显示「置顶」标签；置顶与普通列表之间有浅色细分割线（仅当两组都存在时）。
- 点击置顶：该条目**不要**立即跳到"置顶"分组顶部再消失重现，而是：先原地图标状态切换（描边→实心，`duration-instant`），停留约 150ms 让用户看清反馈，再触发列表重排（用 FLIP 平滑滑动到置顶区，`duration-base` + `ease-in-out`）。
- 直接跳变会让用户产生"我点错了/东西消失了"的困惑；这个"先反馈、后移动"的顺序是这里最重要的细节。

### 3.4 删除（🗑 / 移入回收站）

- 该行：内容先 `opacity→0`（`duration-fast`），随后高度坍缩至 0（`duration-fast`），与之前规范中"列表增删"顺序一致。
- 下方条目自动补位使用 FLIP 平滑上移，不是瞬移。
- 如果是"移入回收站"而非永久删除，可以加一个极轻微的方向暗示：条目在坍缩的同时向左轻移 4px，暗示"移出了当前列表、去了别处"，幅度要克制，不做大范围位移。

### 3.5 网格 / 列表视图切换（顶部两个图标按钮）

- 切换布局模式时，**不建议**做卡片重排的位置动画（网格转列表的元素数量、位置映射关系复杂，强行做 FLIP 容易造成视觉混乱且性能开销大）。
- 直接用整体容器 `opacity` 交叉淡入淡出，`duration-base`，视觉上是"内容整体切了一次页"，比强行做位置插值更干净。

### 3.6 排序下拉（"最新在前"）

- 下拉菜单展开：标准 Popover 动效（`opacity` + `translateY(-4px→0)`，`duration-fast`），见通用规范 3.3 节。
- 选中新排序方式后列表重排：同样用 FLIP，`duration-base`。

## 四、右侧详情面板（联动核心）

这是这套界面里最需要"动效传达关联性"的地方——列表选中和详情面板是两个独立区域，用户需要明确感知到"我点的是这一条，详情面板显示的正是它"。

- **切换详情内容**：不用简单的 `opacity` 淡入淡出（信息量太大，纯淡入淡出会让人在过渡瞬间short读不到内容主体在哪）。推荐：内容整体 `translateY(4px→0)` + `opacity 0→1`，`duration-fast`，方向感极轻微，主要作用是给"内容已更新"一个明确的时间锚点。
- **标题区（纯文本 / 图标 + 文件名）**：不单独做动效，与内容主体同步过渡即可，避免标题和正文错峰产生的割裂感。
- **内容区描边**：与列表同底后，文本正文无框；链接/文件用浅底块、无描边；分区只保留详情头底分隔线（底栏 / 侧栏底部无顶线），靠内边距分隔，避免多层盒子。
- **标签区内边距**：`.preview-tags` 为 `8px 20px 16px`；底栏 `.preview-actions` 上内边距 `8px`，左右仍 `20px` 与内容对齐。
- **底部标签区"+ 添加标签"**：点击后原地展开一个小输入框（`width` 从图标宽度过渡到输入框宽度，`duration-base` + `ease-in-out`，这是少数值得用 width 过渡的场景，因为宽度变化本身就是信息）；确认后新标签 chip 以 `scale(0.9→1)` + `opacity` 方式出现，`duration-fast`。
- **纯文本色值**：整段为 CSS 颜色时详情显示大色块 + 色值（仍为 `text` 类型，无单独动效）。

## 五、底部操作栏（粘贴 / 纯文本 / 收藏 / 置顶 / 删除）

- **主按钮"粘贴"**：按下 `scale(0.97)`，`duration-instant`，松开回弹，不加 spring。
- **粘贴成功反馈**：不建议按钮本身做形态变化（如文字变成"已粘贴"再变回来，容易和"按钮功能改变了"混淆）。推荐右上角轻量 Toast：`translateY(-8px→0)` + `opacity`，停留约 1.5s 后 `ease-in` 快速消失（`duration-fast`），呼应第一版规范里 Toast 的处理原则。
- **次级按钮**（纯文本/收藏/置顶/删除）：仅 hover 背景色变化，无位移无缩放；动效权重一致。**静态色除外**：已收藏 = 金色、已置顶 = 紫、删除危险态 = 红，hover 在同色上加深。

---

## 六、窗口级交互（标题栏）

- 最小化 / 最大化 / 关闭三个按钮：仅 hover 背景色变化，`duration-instant`（这是 Windows 原生窗口控件的用户心智，动效必须比普通按钮更快、更"硬"，不能有任何柔和的过渡感，否则会显得不像系统级控件）。
- 关闭按钮 hover 态用红色背景，其余不变。

---

## 七、优先级建议

如果开发资源有限，按以下顺序实现，性价比从高到低：

1. **列表 hover / 选中态**（三、3.1–3.2）—— 使用频率最高，体感差异最明显
2. **详情面板联动过渡**（四）—— 决定"这个应用是否顺手"的关键细节
3. **置顶/删除的"先反馈后移动"**（三、3.3–3.4）—— 防止误操作困惑
4. **Toast 反馈**（五）—— 低成本高回报
5. 其余（网格切换、标签展开、窗口控件）可以后置，优先级低

## 附录：Token 复用

Clipboard **默认暗色主题**（另有浅色 / OLED / 跟随系统），颜色走 [`src/styles/main.css`](../src/styles/main.css) 的 CSS 变量（`--accent` Fluent 蓝 `#0078d4`、`--type-*`、`--pin`、`--bg-*`、`--text-*` 等）。视觉语义摘要见 [`CLAUDE.md`](../CLAUDE.md)「Theming / tokens」。

动效时长与缓动对齐现有 token（本规范文中的 `duration-*` / `ease-*` 按此映射，不另立一套）：

| 规范用语 | 实现 token |
|----------|------------|
| `duration-instant` | `--transition-instant`（约 50ms） |
| `duration-fast` | `--transition-fast`（约 100ms） |
| `duration-base` | `--transition-normal`（约 180ms） |
| 更长进出场 | `--transition-smooth`（约 280ms） |

缓动已写在各 `--transition-*` 的 `cubic-bezier` 中。关闭设置「动画」或系统「减少动态效果」时，全局压成近 0 时长（`anim-disabled` / `prefers-reduced-motion`）。
